data.txtと対になるようにmeta.jsonを作成する。
そこで行番号と行ID、更新日時のUnixタイムスタンプの組み合わせで管理する。

CodeMirror/collabはOTであり、CRDTよりも行IDを管理・維持しやすいと思う。
サーバ側が責任をもって行IDを維持管理する。クライアントから送られてきたchange setを適用するタイミングでトランザクションで行IDを更新すればいいと思う。

行を分割したり移動したりする場合の行IDの継承のアルゴリズムは保守しやすいように専用のパッケージで管理するのがよいだろう。

おおよそのルール：
改行・結合まわり
	行末で Enter：	元の行がIDを保ち、新しい空行に新IDである
	行頭で Enter：IDが残るのは下の元の行（上の空行は新ID）である
	Backspace で行頭から前行と結合：生き残るのは上の行のIDである
	Delete で行末から次行と結合：生き残るのは現在の行のIDである
	内容を全部消した行（空行は残す）は、IDが保たれる。（空行を消していないので）
	行を丸ごと削除：前後の行のIDが動かない
	消えた行のIDは再利用されない。
	Ctrl+Zで戻す：以前の行IDが復活する
