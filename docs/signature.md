## 要求

権威サーバでクライアントのchenge setを更新するとき、更新時刻がmeta.jsonに書き込まれる。このとき、どのクライアントが更新したかわかるように電子署名も書き込みたい。つまりmeta.jsonは分離署名として機能するようにする。

電子署名は行ごとの内容に対して行いたい。そのためmeta.jsonは、行IDに加えて以下のものも保存する。
行IDと、行内容ハッシュ、updated時刻、システム管理者名、クライアント公開鍵それらに対する電子署名（signiture）

システム管理者名は、通常サーバはAlice, リレーサーバはBobに決め打ちする。PoCなのでこれでOK。
また、通常サーバの公開鍵と秘密鍵(Authority.pem)も今回の署名用のために作成する。

権威サーバの公開鍵はわかりやすいようにリレーサーバ用のknown_hostsに保存する。リレーサーバにおけるknown_hostsの検証機能は今回は実装しない。

また、フロントエンドも今回は実装しない。

## 実装
権威サーバが書く meta.json の各行に、内容ハッシュ、管理者名、クライアント公開鍵、署名を追加しました。コードは未実行で、テストも走らせていません。署名は権威サーバの Authority.pem で行い、data.txt の行内容と meta.json を突き合わせて検証できます(分離署名)。

### 仕様の要点
- 署名対象: "myapp-line-v1\n" + id + "\n" + hash + "\n" + updated + "\n" + admin + "\n" + key に ed25519 で署名し、base64 で signature に保存します。hash は行テキストの SHA-256(hex)です。
- 署名のタイミング: 署名のない行と、ハッシュが現在の内容と合わない行だけを署名し直します。同時に updated も更新するので、変更のない行の署名は変わりません。
- 管理者名とクライアント鍵:
  - リレー経由の接続は Bob で、key はリレーの公開鍵(authorized_keys 形式)です。
  - 直接接続とファイル(data.txt)由来の変更は Alice で、key は空です。
- Authority.pem: serve 起動時に無ければ作成します。
- known_hosts: 起動のたびに known_hosts を1行で上書きします(<addr> ssh-ed25519 AAAA...)。リレー側での検証は実装していません。
- サーバ停止中の編集: 起動時に meta.json を復元した際、停止中に内容が変わった行は Alice が署名し直します。
